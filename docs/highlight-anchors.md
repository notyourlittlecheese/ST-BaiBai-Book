# 重点提示：长期时间线与关系锚点

入口是导航的星形「重点提示」。默认关闭，按聊天启用，不改普通摘要层级、向量候选、embedding 或 reranker。更新后无需迁移现有摘要。

## 使用

1. 勾选「启用重点提示」，勾选代表需要/启用。
2. 可选：展开「从已校对摘要初始化／补充」，输入实际起止楼号。读取有效单楼摘要，不读隐藏的旧正文、不重新摘要。使用现有摘要渠道池，分批付费请求，不做隐式逐楼回退。全部成功后统一审核；失败/停止不会发布中间状态。
3. 日常单楼/批量摘要在原有同一次请求中附带 anchors 提案；没有额外日常请求，但提示和输出 token 会增长。副任务模型是否准确判断心理和场景结束仍取决于模型与审核。
4. 默认长期字段和条目 SUGGEST，当前场景及 Date 为 AUTO。AUTO 自动生效；SUGGEST 审核后生效；LOCKED（包括空值）仅允许手动修改。AI 第一版只新增/更新，不执行删除或合并；用户可手动删除。
5. 正文请求在有待审核提案时等待：确认选中项、沿用原状态继续、或取消本次生成。未勾选=保留旧值；显式「清空」=值为 null，不发送。审核中手动改写内容会按手工记录保护。

初始化每批最多 12 条单楼摘要或约 12000 字符，并携带此前累积的重点草稿；不会自动用高层总结替换人工校对过的单楼摘要。切换插件页或关闭面板不会取消，切换聊天会停止。失败/主动停止后，已完成批次的草稿保留在本次页面会话，可从失败批次继续；中间状态始终不发布。来源或重点设置改变后拒绝复用旧草稿，须手动清除进度。刷新整个酒馆页面会丢失临时进度（含证据），这是不把临时 evidence 持久化的边界。

调用日志显示「重点初始化 i/N · 接口返回成功」，只表示传输成功。初始化页独立显示请求、JSON 解析、重点字段校验、来源检查等阶段的错误，以及失败批次原始响应（仅内存）。重试失败批次仍收费，但不会再次请求已完成批次。旧版本失败时未保存的返回无法在更新后恢复。

## 四层与注入

- relationship_status：Date、Stage、双向态度、双向信任、Boundary。
- current_scene：Meeting、Start、Progress、CurrentActivity、OpenIssue。收束时旧字段清空，与长期提案是否接受无关。
- long_term_timeline：时间与简短历史。插件分配稳定 evt ID；支持人工填写日期、指定插入位置、上下调整。
- relation_facts：持续成立的客观事实。

主开关、四个模块显示开关、每条记录显示开关相互独立。关闭模块不会重写条目自身的显示设置。隐藏时间线可选择仍要显示的直接关联状态；不递归隐藏整张关系网。隐藏事件的 Ref 不输出，但内部仍保留，恢复时可以重现。删除事件解除引用、保留相关状态值。

显示的字数/token 是实际序列化重点文本的估算，不包含酒馆模板；不宣称与各模型 tokenizer 完全一致。注入预览和「记忆检查→上次注入→重点提示」可核对。重点全量发送，不走向量召回。

这些开关只控制重点提示，普通摘要和向量召回不因此关闭。开启但「随摘要更新」关闭时，已有重点可继续注入，副 API 不附带重点任务。

## 依据与来源

日常 USER 态度/信任变化需要本次用户消息的原文片段与楼号；插件校验角色、范围和原文存在。心理语义仍由提示词与用户审核判断，不把“难受”自动等同“委屈/越界”。历史初始化允许信任人工校对的摘要，不冒充用户原话验证。

Evidence 只存在于内存中的待审核提案，确认/放弃后丢弃，不写 chatMetadata。刷新/关闭页面会丢失待审提案，可手动补充。已应用事件只保存来源摘要 ID、楼号和内容指纹，不重复存摘要原文。日常 USER 态度/信任更新另存用户消息位置和指纹；用户消息被修改或标为番外时，对应自动状态也失效。删除前面的消息导致用户消息位置变化时，采用保守失效处理，避免将另一条消息误认成依据。

## 撤销与番外

重点数据保存在当前 chatMetadata.bbs_highlight_anchors_v1，按来源事件重放。删除/修改摘要、来源失效或标记不计入记忆后，相应自动事件不再生效；后续有效楼层事件仍保留，不恢复整份过期快照。取消番外后有效来源可以恢复。

手工编辑/锁定记录不被静默删除：页面提示来源变化，由用户处理。后续 AI 若基于错误历史作出错误判断，数据撤销无法替代语义重审；不会为此自动付费重算。

「不计入记忆」同时隐藏该楼正文，排除摘要、总结派生、锚点和当前聊天向量候选；刷新向量索引和召回缓存。已有自动隐藏不会把番外重新打开。恢复计入时仅恢复由此操作隐藏的原文；原来就手动隐藏的楼保持隐藏。正在进行的请求可能已产生费用，但该楼的迟到返回不能写入。

单楼摘要删除与永久排除是两个操作：楼层面板删除确认中的「此楼继续参与记忆，可重新摘要」默认勾选；取消勾选才同时标记不计入记忆。

## 验证范围

纯重放测试及真实引擎测试覆盖：旧楼撤销不抹掉后来状态、手工/锁定保护、空值、模块/条目隐藏、引用恢复、用户证据校验、部分审核依赖、API 失败与取消、跨批 ID、初始化整批提交、番外不发 API、正常摘要成功但锚点格式失败不重复请求。

当前角色对按聊天 USER/CHAR 解释；不提供群聊多角色关系对切换。手机端真实酒馆交互仍需实机验证。没有新增后端接口。
