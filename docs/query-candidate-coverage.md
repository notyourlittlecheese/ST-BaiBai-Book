# 多 Query 候选覆盖

本地 IndexedDB 与柏宝库后端都经过同一个前端合并入口，不需要升级后端。现有 Query 向量逐个查询，每路取 rerankCandidates 条，最多同时执行两路数据库查询。不会因此增加 embedding 调用次数；多路返回仍包含正文，网络传输和数据库查询量会增加。

只给有有效候选的 Query 分配配额：每 Q 上限为 min(3, floor(总预算 / 有候选 Q 数))。预算小于有候选 Q 数时，按原 Q 顺序轮询最多一个候选并在总预算处停止，调试页提示无法保证全部覆盖。空结果与请求失败不占配额。

保底按轮次选各 Q 第 1、2、3 名，按 leafId 去重。重复或不足腾出的席位留给全局补齐，不追补各 Q 的独占名额。补齐按每条记忆的最高 similarity 排序，最终不超过 rerankCandidates。相同分数用稳定标识打破平局，保持当前 scope 优先的跨 scope 去重规则。

不新增相似度阈值，不按命中 Query 数加权，不改时间权重、精排、全文/摘要分档或最终注入条数。最终候选仍按 similarity 降序交给精排，保留精排失败时原有的排序降级语义。

## 调试

设置 → 向量记忆 → 上次召回详情 → Embedding 检索：

- 每个原始 Q 的单路候选、名次、相似度和来源。
- Q 无结果，与 Q 请求失败分开显示。
- 每个候选标明 Q 保底入选、全局补齐入选或未进入最终 rerankCandidates。
- 最高分所属 Q 与保底所属 Q 分别显示；命中 Q 列表仅指进入过哪些单路 TopN 候选池。
- 查询返回顺序不影响 Q 编号；单 Q 请求中后端返回的 Q0 会映射回原始编号。

策略版本参与召回缓存键，旧策略缓存不会被复用。部分 Q 失败时使用健康查询结果，但不缓存该次不完整结果。诊断快照仅保存摘要预览，不额外保存每路完整正文。

保底只保证单 Q 保底范围内的有效候选进入精排，不保证具体语义一定排名靠前，也不保证通过后续精排和注入阈值。真实剧情应通过单路名次、候选合并、精排和最终注入逐层定位。
